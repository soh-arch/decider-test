# percentile-ranked triage 実装ガイド

Jev に代表される高速判断モデルで、届いた案件に優先度を付け、並べて見せるための方針です。

## 全体の流れ

```
案件到着 → 優先度スコア → 優先度パーセンタイル → 並べる・色で見せる
```

## 1. 優先度スコア

- **各段階に説明を添えて問い、段階ごとの確率を返させる。** 出発点は次の3段階です。言葉は組織に合わせて書き換えます。

  ```
  問い：この案件の緊急度は？
  段階：低い：急ぎではない ／ 中くらい：数日以内に対応 ／ 高い：今すぐ対応が必要
  ```

- **スコアには期待値を使う。** 低い順の段階番号（0, 1, 2, …）に各段階の確率を掛けて合計します。最も確率の高い段階だけを使うと同点が増え、並べられなくなります。
- **同点なら、最上位の段階の確率で並べる。**
- **案件が届いたら、その場で1件ずつ採点する。**

## 2. 優先度パーセンタイル

```
パーセンタイル = (基準集合でスコアが自分より低い件数 + 同点の件数 ÷ 2) ÷ 基準集合の件数 × 100
```

- **比較対象は、固定した基準集合にする。** いま並んでいる案件どうしでは比べません。固定した基準集合と比較すれば、急ぎの案件を処理しても、残った案件の値は繰り上がりません。「普段の案件の中でどのくらい上か」という値の意味が一定に保たれます。
- **パーセンタイルは順位で決まる。** スコアの幅は影響しません。結果を左右するのは、並び順の正しさと同点の少なさです。

### 基準集合

- **中身は過去の案件そのもの。** 処理済みの案件も含め、平凡なものから急ぎのものまで、普段の比率で入れます。
- **「モデル＋問い」の組ごとに1つ持つ。** スコアの分布はこの組で決まるので、モデルか問いを変えたら作り直します。案件の傾向が変わったときも作り直します。
- **版を付けて管理する。** どの基準で求めた値かを、パーセンタイルと一緒に記録します。
- **基準集合は先に採点し、スコアを並べ替えて持っておく。** こうしておけば、新しい案件の位置を二分探索で求められます。

### 出力

1件ごとに、次の値を返します。

- 優先度スコア
- 最上位の段階の確率
- 優先度パーセンタイル
- 基準集合の版

## 3. 見せ方の方針（一例）

画面の種類は問いません。

1. **並び順は優先度スコアで決める。**
2. **色の強さは、優先度パーセンタイルで決める。** 同じ値なら、いつ見ても同じ色になります。
3. **下位はくすんだ色、上位は赤に寄せ、明度・彩度・色相を一緒に変える。** 上位ほど背景との差を大きく、鮮やかにします。色を背景に塗るときは、文字の色を背景の明度に応じて白か黒に切り替えます。
4. **パーセンタイルの数値も添える。**
5. **優先度以外の情報は、別の手段で見せる。** 到着日時の新しさなどは、別の色相・位置・記号で示し、優先度の色とは混ぜません。
6. **採点が済んだ案件から、所定の位置に差し込む。** 採点中の案件は件数だけを示します。

### 色の決め方

- **見た目の明るさに沿って指定できる色空間を使う。** OKLCH などです。こうした色空間を使えば、パーセンタイルの差が見た目の差とそろいます。
- **見た目の色の差が等間隔になるよう、0〜100に割り振る。** 下位から上位への色の道筋に中継点を置き、隣り合う値の色の差（OKLab での距離）が等しくなるよう割り振ります。明るい背景では、上位ほど暗く鮮やかにします。暗い背景では、上位ほど明るく鮮やかにします。
- **具体的な値は画面ごとに決める。** 背景色や文字色との組み合わせで、上位と下位の差がはっきり読み取れる範囲を選びます。

## 4. 運用

- **このツールで参照するのは本文だけ。** 本文に書かれていない事情は、本文に含めて渡すか、並べたあとに人が判断します。
- **質問の仕方を変えたら、自分たちの案件で並び順を確かめてから使う。**
